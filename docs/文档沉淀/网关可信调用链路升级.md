# 网关可信调用链路与知识沉淀闭环

> 范围：请求可信边界、完整对话记录、Candidate 审核、知识卡发布与知识投影。

## 目标

将外部模型调用转化为**可追溯、可审核、可发布**的知识资产，同时确保原始 API Key 不进入业务上下文、审计日志或知识数据。

## 可信调用链

```text
HTTP 请求
  → 服务端生成 request_id
  → API Key 校验并提取可信身份
  → Controller 组装 ProxyCallContext
  → ProxyService 执行协议转换、安全扫描、上游调用与审计
  → GatewayService 负责受控出站 HTTP / SSE
```

- `request_id` 由服务端生成，写入 `request.state` 并以 `X-Request-ID` 返回；客户端同名 Header 不可信。
- 鉴权仅保留 `api_key_id`、`api_key_name` 等可信身份，原始 Key 不传入服务层。
- `ProxyCallContext` 是框架无关的上下文对象；RAG、Agent 和后台任务无需依赖 FastAPI `Request`。
- 上游调用携带受控 `X-Request-ID`，审计日志以 `trace_id=request_id` 关联整个链路。

## SSE 真实终态

流式转发使用 `httpx.AsyncClient.stream()` 与 async generator；只有收到真实 `[DONE]` 才属于完成态。

| 终态 | 含义 | 是否沉淀 |
|---|---|---:|
| `completed` | 收到真实 `[DONE]` | 是 |
| `failed` | 上游、网络或协议异常 | 否 |
| `canceled` | 客户端断连或取消 | 否 |
| `blocked` | 安全规则阻断 | 否 |

非流式调用也必须在响应通过成功结构校验后才视为完成。失败、取消、阻断和 EOF 均不会伪装为完成或写入知识链路。

## 从完整对话到 Candidate

```text
完成态调用
  → request_logs
  → conversation_records
  → conversation_candidates (pending_review)
```

- `conversation_records` 关联 `request_log_id`、`trace_id`、渠道、模型、请求和响应正文；同一请求日志最多一条。
- `conversation_candidates` 仅保存来源记录、状态、规则版本和时间，不复制对话正文或敏感认证数据。
- Candidate 入池只在日志和完整对话记录均成功后发生；入池失败不会改变已返回的网关响应。

## 人工治理知识闭环

```text
pending_review
  → approved / rejected
  → 草稿（AI 生成或人工创建）
  → 管理员选择 kb_id 发布
  → 不可变知识卡版本
  → KB 文档、Wiki、图谱投影
  → graph_hybrid RAG
```

- 管理 API 使用 `ADMIN_API_KEY` 与 `X-Admin-API-Key`，未配置密钥时 fail-closed。
- AI 只生成草稿和图谱建议；管理员审核并发布前，内容不会进入普通 RAG。
- 每次发布创建不可变知识卡版本；已发布内容通过新草稿修订产生后续版本，不覆盖历史版本。
- KB、Wiki 与图谱是知识卡版本的可重建投影，保留来源版本、证据和置信度。
- `graph_hybrid` 仅在同一知识库中做一跳扩展，最多补充三条图谱来源；图谱异常时回退普通混合检索。

## 核心原则

1. 服务端拥有请求关联 ID，调用方输入不能覆盖可信链路。
2. 鉴权一次完成，后续仅消费可信身份上下文。
3. 仅完整调用才可进入审核队列。
4. 仅管理员审核并发布的内容才可成为知识资产。
5. 知识卡版本是事实源，KB、Wiki 和图谱均为可重建投影。
6. 任何 AI 输出均为建议，不能绕过人工发布门禁。
